# Handover: how BILBIES! for the Microbee works

## Memory

| Where | What |
|---|---|
| 8000h–CBFFh (block 0, upper) | The program (`src/main.asm`), `BILBIES.BIN` |
| CC00h–E901h | Render tables, page tables, bounce buffer, IM 2 vector (`vars.asm`) |
| E910h–EE4Dh | Game variables (`GVARS`, names as in the VZ original) |
| EFF0h down | Stack |
| F000h–F7FFh | Video window: screen RAM or attribute RAM (port 1Ch b4) |
| F800h–FFFFh | PCG bank (port 1Ch) or colour RAM (port 08h b6) |
| Block 1 | WORLD: bitmap 1024 × 160 (column-major), colour map, dug colours, header, mask, minimap, script |
| Block 2 | Front-end work space |
| Blocks 4–7 | Sprites (`SPRn.BNK`) |
| Blocks 12–19 | Packed levels, colour and mono (`LEVn.BNK`) |
| Block 27 | HUD font and buttons (`GFX.BNK`). Not block 3: the CP/M BIOS uses block 3 as a buffer while loading |

The assembler checks that the tables don't run into the game variables.

## Screen

The screen is 64 × 16 cells, 16 lines each (`crtc_game`).

- **Rows 0–9: the playfield, 512 × 160 pixels.** Each cell is a PCG
  glyph of its own. The glyph column is world column mod 64, and a
  column's 160 bytes are contiguous at F800h + (gc mod 12) × 160.
- **Two pages.** Page 0 uses PCG banks 0–5 and page 1 banks 6–11. The
  shown page is flipped with the 6545's start address (0 or 400h).
- **Rows 10–15: the HUD**, from banks 12–15.

Each frame:

1. **Restore.** The world bitmap is copied back over the columns that
   sprites dirtied last time on this page, using dirty lists and unrolled
   LDI.
2. **Draw sprites.** Pre-shifted 1-bit frames with an AND mask are
   blitted straight into the glyphs. The blit is SP-pop unrolled code,
   with interrupts off for each column.
3. **Colour.** Cells a sprite touched get yellow ink, keeping their
   paper.
4. **HUD and flip.**

Scrolling is 8 pixels at a time. It rewrites codes, attributes and
colours, and loads only the new columns (`load_col`).

## Game logic

`src/game.asm` is the VZ original with only these changes:

- Pixel changes go to `world_px` / `world_dug` / `world_brick`, which
  update the 2× bitmap and colours.
- `rand` is `vrand`.
- A `vschk` call goes in the creature loop.
- Sound calls.

The rules run on the original 512 × 80 mask. Positions are drawn at 2×,
interpolated between ticks.

## Timing

There is no timer interrupt. `vschk` counts rising edges of the 6545's
vertical blanking bit. Long loops call it so that no edge is missed.
`waitfields` waits for the frame's fields and carries over at most one
extra.

## Sound

- **Effects (`sound.asm`).** The busy loops call `SND n`, where n is the
  time since the last call in 64-T units. Each site's n was measured
  with `tools/sndcal.py`. The service is a single RET when no effect is
  playing. Effect scripts are the VZ's: one step per update.
- **Music (`music.asm`).** This is the VZ's three-voice player, with a
  169 T sample loop and OUT 02h. It plays only in idle time
  (`mus_wait` from `waitfields` / `vsync1`), with interrupts off, until
  the next blanking. It stops when the mouse's clock line changes. The
  song data comes from `tools/mkmusic.py`; regenerate the note table if
  the loop timing changes.

## Mouse

The mouse is the Microsoft protocol, wired as in uBee512: PIO B b2 = DTR
bit clock (one IM 2 interrupt per bit), and b3 = CTS data (inverted).
`mouse_isr` frames the bits and builds `ms_dx`, `ms_dy` and `ms_btn`.

## Disk and saving

- **Disk (`tools/build_disk.py`).** DS80 format: 80 × 2 × 10 × 512, 3:1
  skew, 4K blocks, boot tracks and CCP from uB-Type. `SAVE.DAT` is
  always the first directory entry, in block 1.
- **Loader (`BILBIES.COM`, `src/loader.asm`).** Finds CP/M's bank,
  checks for 1 MB, loads each file into its block, then maps the program
  and jumps to 8000h.
- **Saving (`save.asm`).** Drives the WD2793 directly. Before every
  write it checks that directory entry 0 is still `SAVE.DAT`, then
  writes, reads the record back and verifies it.

## Art

Generated by Python from the original level descriptions:

- `tools/world.py` paints the levels: materials, skies, scenery, the
  hatch, the exit, and the cell colour compiler.
- `tools/stamps_hi.py` has the 50 pictures.
- `tools/bilby.py` has the bilbies.
- `tools/preview_art.py` writes preview sheets.

The rules for a cell's colours: terrain is always ink where ground meets
air, paper is never yellow, white or light cyan (so that yellow bilbies
show), and mono uses only paper 0/8 and ink 7/15.

## Ideas not done

- Clash: keep the yellow recolour off the ground row (bilby ink only in
  air cells), or use a darker bilby on light paper.
- Speed on the 30–40 bilby levels: draw only the creatures that moved,
  merge the restore and blit passes, cache the shifted frames.
- 4-pixel scrolling: PCG glyphs would need re-shifting per step, which
  costs about a full frame.
- Title music during the attract demos (it is stopped there now).
